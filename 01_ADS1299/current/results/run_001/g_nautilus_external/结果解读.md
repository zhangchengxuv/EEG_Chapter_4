# 为什么混淆矩阵右侧两列全是零

这张图的行是真实类别，列是预测类别。预测CSV与图像已逐项核对，计数一致：

| 类别 | 真实试次数 | 被模型预测为该类的次数 |
| --- | ---: | ---: |
| A | 85 | 237 |
| B | 84 | 102 |
| C | 88 | 0 |
| D | 82 | 0 |

因此，右侧C/D两列的零表示：**模型在全部339个g.Nautilus外部试次中，一次也没有把C或D选为最高概率类别。** 这不表示真实数据没有C/D，也不表示四分类网络只有两个输出。

从实际softmax概率看，全部试次中C概率的最大值约0.469%，D概率的最大值约1.211%，都没有胜过同一试次中的A/B。概率不等于计数；矩阵中的0统计的是最终argmax类别。

正确数为A类70次加B类44次，总计114/339=33.63%。真实C类88次、D类82次全部被误分到A或B，所以外部C/D召回率为0，宏F1仅0.2270。该模型当前不能可靠地跨设备识别四类。

ADS1299内部测试中四类各32次全部正确，说明网络的四分类输出和标签映射正常；本次外部输入发生了明显的预测偏向。两个设备的幅值、参考、噪声及滤波处理差异都可能影响结果。特别是g.Nautilus已有30Hz低通和4Hz高通，而ADS1299训练信号原处理为1～80Hz，这些差异可能改变模型依赖的频谱信息。

以上是可能机制，不是已经定位出的唯一原因。未通过频带消融或新独立验证确定各因素贡献，不能据此断言某设备更差、某个通道损坏或一定存在过拟合。也没有根据这批外部成绩重新标准化、调参或删除试次。
